# AGENTS.md

This file contains repository-specific instructions for coding agents and automated contributors. These instructions apply to the entire repository.

## Project overview

SafAI is a Safari Web Extension and macOS containing app. The extension is written in modern JavaScript, HTML, and CSS, then bundled for Safari 15.4. The macOS wrapper is generated by Apple's Safari Web Extension packager.

## Current behavior and verification

- Reading tools add a closed-shadow selection menu (explain/translate/outline/follow-up), exact source lookup with temporary highlights, up to three explicitly selected comparison tabs, and locally saved editable/reorderable quick prompts. Selection actions fill a draft only; switching from comparison to a new quick selection clears comparison sources. Password/editable fields are excluded from the floating menu.
- The user explicitly approved persistent access to all general HTTP/HTTPS websites and tab metadata. Top-frame content scripts install reading controls, but do not gather all tab bodies. Listing tabs reads metadata only; the panel must explicitly select pages before the background injects the bounded reader. Incognito/non-web/other-window targets are rejected. Content preference requests return only `selectionTools`, never API settings or keys. Keep privileged reading/locating messages restricted to the extension panel sender.
- Comparison reads are all-or-nothing, with navigation/permission checks and 16,000 characters per page. API sends reread selected pages; ChatGPT handoff uses the attached, previewable snapshots. Comparison payloads exclude the unselected current page and its selection. Source excerpts partition bounded text without duplicating/dropping it; current-page sources cap at 32, comparison pages at 14. Citation buttons accept only IDs from that request's sources. Source excerpts and comparison snapshots are not persisted with history; reopening a saved transcript retains citation text but not live locator buttons.
- Sidebar opening/closing interpolates page reservation and host translation over 250ms, supports reversals, and respects reduced motion. Dragging remains immediate; captures/picking settle motion and suspend selection UI/highlights. Site media/fixed adjustments run at endpoints, not every frame. Synthetic native sampling observed 25 intermediate widths between 1473px and 1131px.
- Native Safari reading-tool verification covers selection-to-draft without sending, quick-prompt save, reading two selected loopback pages, reading a newly opened example.org page without a per-site prompt, actual configured-provider inference containing two source IDs, and clicking a citation switching to the correct tab with an exact text highlight. Comparison-to-quick-selection switching and viewport capture/preview without sidebar/tool overlays were also checked. Safari rejects port numbers in permission match patterns; permission descriptors use scheme/hostname while document/API URLs keep their port. Node tests also cover cancellation/timeouts, stale settings, invalid/ambiguous sources, and source exclusion. No permission for JavaScript from Apple Events was enabled; authorized System Events were used for native keyboard testing.
- Page reflow now narrows the root content width (instead of adding root padding), shifts accessible stylesheet width breakpoints, and compensates viewport-fixed controls. It preserves authored inline values/media conditions on close and suspends these adjustments for viewport capture. Dynamic fixed candidates are rescanned in bounded batches; extension shadow UI is excluded. No new permissions or network requests are introduced.
- Reflow is an approximation, not a native Safari sidebar: cross-origin rule bodies, CSSOM-only inserted rules, range-style media queries, shadow/adopted stylesheets, viewport units and JavaScript viewport measurements may retain full-window behavior. The local fixture `tests/fixtures/reflow-page.html` covers columns, viewport-fixed headers and translated centered controls.
- X has an exact-host scoped layout adaptation: its main/article columns can shrink, while the secondary column keeps its internal authored width. Below 1000px of remaining page space the secondary column is hidden; closing the panel restores it. No navigation controls are removed. This addresses X's fixed 600px article and 350px secondary-content widths rather than shrinking all page text.
- Installed native Safari verification covers the original X post at 322px and 514px sidebar widths, secondary-column visibility, closing/restoring the original layout, and a fresh synthetic reflow page reporting 1131px available/content width. Viewport capture and its preview were verified on the synthetic page: full-width page without the sidebar, followed by restored reflow. Element capture retains previous validation and automated coverage; it was not repeated in this reflow pass. AppleScript foreground activation/System Events were authorized for testing; Safari's disabled JavaScript-from-Apple-Events setting was not changed. These checks do not establish universal website compatibility.
- The approved `design/safari-sidebar/` appearance is integrated into the production extension: one compact toolbar, continuous glass material, 322px default visible width, 10px outer gutters, and 22px corners. The isolated prototype remains a synthetic design reference, not a shipped page.
- Glass is rendered in the closed shadow host behind the transparent extension iframe, not by exposing webpage data to the panel. System light/dark appearance and reduced transparency/motion remain supported.
- History replaces the conversation region and supports title search; toolbar navigation remains available. Model/mode and capture controls use compact popovers with Escape dismissal and keyboard focus handling. Settings and screenshot previews remain modal.
- Local text-only history retains 25 conversations with bounded message sizes. The API receives the latest 12 history messages; screenshots and page snapshots are not persisted.
- All production settings/conversation writes go through `background/storage.js` and one serialized `core/shared-store.js` writer. Settings are field patches with stale-form conflict checks; conversation writes append only new messages and selection updates never replace the history list. Existing `settings`/`conversations` storage schema is retained.
- Only the extension panel's own sender ID and URL may invoke storage mutations. Never route these mutations through the webpage/content bridge or return keys to a content-script sender. Permission rechecks and old-origin cleanup run inside the same write queue.
- Panels observe local-storage changes and reread on focus/visibility return. API sending checks the latest settings and keeps an immutable per-request snapshot; missing endpoint permission must be granted by saving the settings form, not by silently reauthorizing an old endpoint during send.
- Cross-panel synthetic tests cover concurrent settings edits, stale forms, separate/same-conversation appends, failed writes, and permission cleanup races. Native Safari has verified a settings toggle saved in one tab, read by a second tab, and synchronized back without reload; that preference was restored afterward. Existing keys/conversations were not replaced for testing.
- Failures must surface, not become defaults, empty history, simulated answers, or unsolicited downloads. Storage-read failure prevents initialization from binding mutating controls. First-use missing values still receive documented defaults.
- API parsing rejects malformed, empty, incomplete, or explicitly truncated answers. Requested context read failures block sending; retries of an unchanged page can recover.
- Keep narrow handling of expected untrusted math syntax and stream cleanup; do not remove security boundaries or Safari accessibility support merely to reduce catch counts.
- Explicit `/panel.html?demo` is an in-memory UI preview only. Use `tests/fixtures/reading-page.html` for real Safari interaction without personal data. Tests execute bundled panel/content code and real loopback HTTP streaming/error scenarios.
- The local installed app is `/Applications/SafAI.app`, copied from the signed Release build at `output/DerivedDataRelease/Build/Products/Release/SafAI.app`. Debug output remains under `output/DerivedData/`; generated packaging remains under `SafariApp/`. These are ignored artifacts, not source. Rebuild and verify target-environment behavior after changes; do not infer that provider inference or screenshot capture works from compilation alone.
- Keep Safari registered to the Applications copy, not concurrent Debug/Release build copies. Duplicate registrations were removed during installation verification; after updating, reload already-open webpages so they do not retain an older panel script.
- Toolbar opening uses direct `scripting.executeScript` calls to an isolated-world controller, with checked acknowledgements and an error badge on failure. Do not restore the `tabs.sendMessage` toggle path: native Safari testing returned undefined without delivering the message to even a minimal receiver. The controller is published only after initialization succeeds.
- Capture fails explicitly and restores the sidebar if painting or capture stalls. Dialog opening must not depend on transition progress.
- Verification prioritizes the installed Safari extension. Native foreground Safari has verified open/close/reopen, viewport capture without the sidebar, element capture cropped to the selected button, both image previews, toolbar, settings and history switching. DOM tests supplement these checks. Provider inference and other Safari versions are separate validation scopes.
- Safari reports the existing IPv6-literal CSP source `http://[::1]:*` as invalid; IPv6 loopback provider connectivity is not validated. This warning was not the cause of the toggle-message failure; use a separate scoped fix rather than relaxing all HTTP sources.

## Source of truth

- Edit extension code in `src/`.
- Edit build and packaging behavior in `scripts/`.
- Add or update tests in `tests/`.
- Treat `dist/` as generated output; never edit or commit it.
- Treat `SafariApp/` as generated output and do not commit it. Run `npm run package:safari` to regenerate the Xcode project.
- When dependencies change, update and commit `package-lock.json`.

## Required workflow

1. Inspect the relevant source and existing tests before changing behavior.
2. Add a failing regression test before implementing a feature or bug fix when practical.
3. Keep changes focused and preserve unrelated user work.
4. Run `npm test` and `npm run build` before reporting completion.
5. Run `npm run package:safari` when the Xcode project or embedded extension resources must be refreshed.
6. For packaging-sensitive changes, run the unsigned Xcode build documented in `README.md`.

## Code conventions

- Use ES modules and APIs compatible with Safari 15.4.
- Prefer small modules with explicit inputs over shared mutable state.
- Keep UI text consistent with the existing Traditional Chinese interface.
- Preserve accessible names, focus behavior, keyboard controls, and the Safari 15.4 `inert` fallback.
- Use `node:test` and `node:assert/strict` for tests.
- Use `apply_patch` or focused edits; do not rewrite generated bundles manually.
- Keep `README.md` and other public documentation in English unless a maintainer requests otherwise.

## Privacy and security invariants

- Never commit real API keys, tokens, credentials, provisioning profiles, signing certificates, or user browsing data.
- Never log or expose extension storage, API keys, page context, clipboard contents, screenshots, bridge tokens, or privileged extension APIs to webpage scripts.
- Treat all webpage content and AI output as untrusted.
- Keep Markdown and KaTeX rendering sanitized. Do not enable raw HTML, remote images, unsafe URL schemes, or trusted KaTeX commands.
- Keep scripts, styles, fonts, and other runtime assets local; do not add CDNs or remote code.
- Persistent general website access is user-approved for reading tools; do not automatically transmit browsing data or broaden access beyond HTTP/HTTPS. Changing an API endpoint must not remove shared mandatory website permissions.
- Require HTTPS for remote endpoints. Loopback HTTP is allowed only without an API key.
- Keep screenshot, context, response, and metadata size limits intact unless a reviewed change explicitly replaces them.
- Preserve active-tab checks around screenshot capture and reject stale capture results after a tab switch or layout change.
- Preserve the tokenized `MessageChannel` boundary between the host page and extension panel.
- Any new permission or external request requires an explicit explanation and tests.

## Generated files and public-repository safety

- Do not commit `node_modules/`, `dist/`, `output/`, `SafariApp/`, `.playwright-cli/`, Xcode user data, environment files, or signing material.
- Review staged files with `git diff --cached` before every commit.
- Run a sensitive-value scan before publishing changes from a machine that has local API or signing credentials.
- Do not place development-team identifiers or personal signing identities in documentation or scripts.
